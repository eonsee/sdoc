这一章把前面的设计落到代码。主线是 **RuoYi-Vue 单体 + 独立 Collector 采集服务**。如果你用 RuoYi-Cloud 或 RuoYi-Vue-Plus，目录和依赖会变，但表结构、采集流程、碳核算思路不变。

## 1. 环境准备

| 软件 | 版本 | 用途 |
| --- | --- | --- |
| JDK | 8 或 17 | 后端 |
| Maven | 3.9+ | 构建 |
| MySQL | 8.0+ | 业务库 |
| Redis | 7.x | 缓存 |
| Node | 20 LTS | 前端 |
| Git | 最新 | 版本管理 |
| TDengine | 3.3.x | 时序库 |
| EMQX | 5.8.x | MQTT |
| Docker | 26+ | 本地中间件 |

<Steps>
  <Step title="拉取若依">
    ```bash
    git clone https://gitee.com/y_project/RuoYi-Vue.git
    git clone https://gitee.com/y_project/RuoYi-Vue3.git
    ```
  </Step>
  <Step title="初始化数据库">
    在 MySQL 里创建 `ry-vue` 库，执行若依 `sql` 目录下的 `ry_2025xxxx.sql` 和 `quartz.sql`。具体文件名以你拉取的版本为准。
  </Step>
  <Step title="启动 Redis 和 MySQL">
    本地可以用 Docker：
    ```bash
    docker run -d --name ry-mysql -p 3306:3306 \
      -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=ry-vue mysql:8.0
    docker run -d --name ry-redis -p 6379:6379 redis:7.2
    ```
  </Step>
  <Step title="修改配置并启动">
    改 `ruoyi-admin/src/main/resources/application-druid.yml` 里的数据库连接，改 `application.yml` 里的 Redis 连接。启动 `RuoYiApplication`，浏览器打开前端，默认账号 `admin/admin123`。
  </Step>
</Steps>

<Aside type="warning" title="上线前必须改默认密码">
  若依默认账号和密码是公开的。上线前修改 `admin` 密码，删除或禁用演示账号，修改数据库、Redis、MQTT 的默认口令，并检查 `application.yml` 里是否还有开发环境的明文密码。
</Aside>

### 2.3 Mapper 扫描

若依默认扫描 `com.ruoyi.**.mapper`，如果你的包在 `com.ruoyi.energy.mapper` 下，通常不用改。如果启动时报 Mapper 找不到，检查启动类上的 `@MapperScan` 或 `application.yml` 里的 `mybatis.typeAliasesPackage`、`mapperLocations`。

```yaml title="application.yml（节选）"
mybatis:
  typeAliasesPackage: com.ruoyi.**.domain
  mapperLocations: classpath*:mapper/**/*Mapper.xml
```

## 3. 数据库设计

能碳系统的表可以分成五组：

| 分组 | 表 | 说明 |
| --- | --- | --- |
| 基础数据 | `energy_media`、`energy_meter`、`energy_point`、`energy_gateway` | 介质、计量点、点位、网关 |
| 采集数据 | TDengine `point_data` | 原始值、质量码 |
| 统计数据 | `energy_stat` | 小时/日/月聚合 |
| 碳管理 | `carbon_factor`、`carbon_accounting`、`carbon_emission` | 因子、核算任务、核算明细 |
| 业务管理 | `energy_price`、`energy_quota`、`energy_alarm_rule`、`energy_alarm` | 单价、定额、报警 |

下面给出核心表的建表语句。字段按若依习惯保留 `create_by`、`create_time`、`update_by`、`update_time`、`remark`，方便代码生成和审计。

### 3.1 能源介质


## 4. 用代码生成器做 CRUD

<Steps>
  <Step title="导入表">
    启动若依，进入“系统工具 → 代码生成 → 导入”，勾选业务表。
  </Step>
  <Step title="配置生成信息">
    包名填 `com.ruoyi.energy`，模块名填 `energy`，业务名填 `meter`、`point` 等。作者、菜单名称按项目填。
  </Step>
  <Step title="生成并解压">
    下载生成的压缩包，把 `main/java`、`main/resources`、`vue` 下的文件分别放到 `ruoyi-energy` 和前端项目对应目录。
  </Step>
  <Step title="手工改造">
    生成的是标准单表 CRUD。你需要补：联表查询介质/部门名称、参数校验、数据权限、导入导出模板、点位与计量点的一致性校验。
  </Step>
</Steps>

生成后的 Controller 通常长这样，记得加权限注解：

```java
@RestController
@RequestMapping("/energy/meter")
public class EnergyMeterController extends BaseController {

    @Autowired
    private IEnergyMeterService meterService;

    @PreAuthorize("@ss.hasPermi('energy:meter:list')")
    @GetMapping("/list")
    public TableDataInfo list(EnergyMeter meter) {
        startPage();
        List<EnergyMeter> list = meterService.selectMeterList(meter);
        return getDataTable(list);
    }

    @PreAuthorize("@ss.hasPermi('energy:meter:query')")
    @GetMapping("/{meterId}")
    public AjaxResult getInfo(@PathVariable Long meterId) {
        return success(meterService.selectMeterById(meterId));
    }

    @PreAuthorize("@ss.hasPermi('energy:meter:add')")
    @Log(title = "计量点", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@Validated @RequestBody EnergyMeter meter) {
        return toAjax(meterService.insertMeter(meter));
    }

    @PreAuthorize("@ss.hasPermi('energy:meter:edit')")
    @Log(title = "计量点", businessType = BusinessType.UPDATE)
    @PutMapping
    public AjaxResult edit(@Validated @RequestBody EnergyMeter meter) {
        return toAjax(meterService.updateMeter(meter));
    }

    @PreAuthorize("@ss.hasPermi('energy:meter:remove')")
    @Log(title = "计量点", businessType = BusinessType.DELETE)
    @DeleteMapping("/{meterIds}")
    public AjaxResult remove(@PathVariable Long[] meterIds) {
        return toAjax(meterService.deleteMeterByIds(meterIds));
    }
}
```

## 5. 采集服务

### 5.1 为什么独立部署

采集服务要长期运行、直接连现场网络、频繁重连，和 Web 应用的生命周期不同。独立部署后：

- Web 应用重启不影响采集。
- 采集服务可以部署在靠近网关的机器。
- 只给采集服务开放时序库写权限和 MQTT 订阅权限。

```java
@Service
public class MqttIngestService implements MqttCallbackExtended {

    private static final Logger log = LoggerFactory.getLogger(MqttIngestService.class);

    @Value("${mqtt.broker}")
    private String broker;
    @Value("${mqtt.client-id}")
    private String clientId;
    @Value("${mqtt.username}")
    private String username;
    @Value("${mqtt.password}")
    private String password;
    @Value("${mqtt.qos:1}")
    private int qos;

    private final ObjectMapper objectMapper = new ObjectMapper();
    private final TimeSeriesWriter writer;
    private final LatestValueCache cache;
    private final AlarmEvaluator alarmEvaluator;

    private MqttClient client;

    public MqttIngestService(TimeSeriesWriter writer,
                             LatestValueCache cache,
                             AlarmEvaluator alarmEvaluator) {
        this.writer = writer;
        this.cache = cache;
        this.alarmEvaluator = alarmEvaluator;
    }

    @PostConstruct
    public void start() throws MqttException {
        client = new MqttClient(broker, clientId, new MemoryPersistence());
        MqttConnectOptions options = new MqttConnectOptions();
        options.setUserName(username);
        options.setPassword(password.toCharArray());
        options.setAutomaticReconnect(true);
        options.setCleanSession(false);
        options.setKeepAliveInterval(30);
        client.setCallback(this);
        client.connect(options);
        client.subscribe("energy/+/+/telemetry", qos);
        client.subscribe("energy/+/+/status", qos);
        log.info("MQTT connected: {}", broker);
    }

    @Override
    public void connectComplete(boolean reconnect, String serverURI) {
        try {
            client.subscribe("energy/+/+/telemetry", qos);
            client.subscribe("energy/+/+/status", qos);
            log.info("MQTT reconnected, resubscribed: {}", serverURI);
        } catch (MqttException e) {
            log.error("resubscribe failed", e);
        }
    }

    @Override
    public void messageArrived(String topic, MqttMessage message) {
        try {
            String payload = new String(message.getPayload(), StandardCharsets.UTF_8);
            if (topic.endsWith("/status")) {
                handleStatus(topic, payload);
            } else {
                handleTelemetry(topic, payload);
            }
        } catch (Exception e) {
            log.error("handle message failed, topic={}", topic, e);
        }
    }

    private void handleTelemetry(String topic, String payload) throws Exception {
        JsonNode root = objectMapper.readTree(payload);
        String gatewayId = root.path("gatewayId").asText();
        String meterCode = root.path("meterCode").asText();
        String energyType = root.path("energyType").asText("");
        long ts = root.path("ts").asLong(System.currentTimeMillis());
        int quality = root.path("quality").asInt(0);
        JsonNode points = root.path("points");

        Iterator<Map.Entry<String, JsonNode>> it = points.fields();
        while (it.hasNext()) {
            Map.Entry<String, JsonNode> entry = it.next();
            String pointCode = meterCode + "." + entry.getKey();
            double value = entry.getValue().asDouble();
            writer.append(pointCode, meterCode, energyType, ts, value, quality);
            cache.update(pointCode, value, ts, quality);
            alarmEvaluator.evaluate(pointCode, value, ts);
        }
    }

    private void handleStatus(String topic, String payload) {
        // 解析网关心跳，更新在线状态和最后心跳时间
        log.debug("gateway status: {} {}", topic, payload);
    }

    @Override
    public void connectionLost(Throwable cause) {
        log.error("MQTT connection lost", cause);
    }

    @Override
    public void deliveryComplete(IMqttDeliveryToken token) {
        // 采集服务只订阅，不发布，忽略
    }
}
```

<Aside type="note" title="ClientId 不能重复">
  EMQX 里同一个 ClientId 的后连接会踢掉前连接。多个采集实例要用不同 ClientId，或者用 `clientId + 随机后缀`。生产环境建议用 `collector-{hostname}`。
</Aside>

<Aside type="tip" title="生产环境的两处改造">
  - 把 `MemoryPersistence` 换成 `MqttDefaultFilePersistence`，否则进程重启后 QoS 1 的未确认消息会丢。
  - 在启动类加 `@EnableScheduling`，`@Scheduled` 的批量写和 Modbus 轮询才会生效。

```java
@Component
public class TimeSeriesWriter {

    private static final Logger log = LoggerFactory.getLogger(TimeSeriesWriter.class);

    private final BlockingQueue<PointSample> queue = new LinkedBlockingQueue<>(100000);
    private final DataSource dataSource;
    private final int batchSize;
    private final long flushIntervalMs;

    public TimeSeriesWriter(@Qualifier("tdengineDataSource") DataSource dataSource,
                            @Value("${tdengine.batch-size:500}") int batchSize,
                            @Value("${tdengine.flush-interval-ms:1000}") long flushIntervalMs) {
        this.dataSource = dataSource;
        this.batchSize = batchSize;
        this.flushIntervalMs = flushIntervalMs;
    }

    public void append(String pointCode, String meterCode, String energyType,
                       long ts, double value, int quality) {
        boolean offered = queue.offer(
                new PointSample(pointCode, meterCode, energyType, ts, value, quality));
        if (!offered) {
            log.warn("collector queue full, dropping sample: {}", pointCode);
        }
    }

    @Scheduled(fixedDelayString = "${tdengine.flush-interval-ms:1000}")
    public void flush() {
        List<PointSample> batch = new ArrayList<>(batchSize);
        queue.drainTo(batch, batchSize);
        if (batch.isEmpty()) {
            return;
        }
        try (Connection conn = dataSource.getConnection()) {
            conn.setAutoCommit(false);
            try (Statement stmt = conn.createStatement()) {
                for (PointSample s : batch) {
                    stmt.addBatch(buildInsertSql(s));
                }
                stmt.executeBatch();
                conn.commit();
            }
        } catch (Exception e) {
            log.error("flush to TDengine failed, size={}", batch.size(), e);
            // 失败时放回队列，等待下一次重试（生产环境要做幂等和限流）
            queue.addAll(batch);
        }
    }

    private String buildInsertSql(PointSample s) {
        String table = "p_" + Math.abs(s.getPointCode().hashCode());
        String sql = "INSERT INTO energy." + table
                + " USING energy.point_data TAGS ('" + esc(s.getPointCode()) + "','"
                + esc(s.getMeterCode()) + "','" + esc(s.getEnergyType()) + "',0)"
                + " VALUES (" + s.getTs() + "," + s.getValue() + "," + s.getQuality() + ")";
        return sql;
    }

    private String esc(String value) {
        return value == null ? "" : value.replace("'", "''");
    }
}
```

<Aside type="danger" title="示例 SQL 只用于教学">
  上面的拼接 SQL 必须做标识符和字符串转义。生产环境应使用参数化写入、固定子表映射、批量接口，并对 `pointCode` 做白名单校验。直接把外部 MQTT 内容拼进 SQL 是严重的安全漏洞。
</Aside>

### 5.7 Modbus 轮询

如果网关只做透明传输，采集服务也可以直接轮询 Modbus TCP：

```java
@Service
public class ModbusPollingService {

    private static final Logger log = LoggerFactory.getLogger(ModbusPollingService.class);

    @Scheduled(fixedDelay = 60000)
    public void poll() {
        // 实际项目从数据库加载启用的网关和点位，这里用示例参数
        ModbusMaster master = null;
        try {
            master = ModbusMasterFactory.createModbusMasterTCP("192.168.10.11", 502);
            master.setResponseTimeout(3000);
            master.connect();

            // 从站地址 3，起始寄存器 0，读 10 个寄存器
            ReadHoldingRegistersRequest request =
                    new ReadHoldingRegistersRequest(3, 0, 10);
            ReadHoldingRegistersResponse response =
                    (ReadHoldingRegistersResponse) master.processRequest(request);

            int[] regs = response.getRegisters();
            double voltageA = regs[0] * 0.1;
            long energyRaw = ((long) regs[8] << 16) | (regs[9] & 0xFFFFL);
            double energy = energyRaw * 0.01;

            log.info("UA={}V, EP={}kWh", voltageA, energy);
        } catch (Exception e) {
            log.error("modbus poll failed", e);
        } finally {
            if (master != null) {
                try {
                    master.disconnect();
                } catch (Exception ignored) {
                }
            }
        }
    }
}
```

<Aside type="caution" title="不要每分钟新建连接">
  示例为了简洁，每次轮询都建连接。生产环境要复用连接、做超时和重连、按网关串行轮询，避免把仪表打挂。一个网关下的表要排队读，不要并发轰。
</Aside>

### 6.2 聚合逻辑

累计量（电量、水量、气量）取周期内首尾差；瞬时量（功率、流量、温度）取平均/最大/最小。

```java
@Service
public class EnergyStatServiceImpl implements IEnergyStatService {

    @Autowired
    private EnergyPointMapper pointMapper;
    @Autowired
    private TimeSeriesQueryDao timeSeriesQueryDao;
    @Autowired
    private EnergyStatMapper statMapper;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void aggregateHour(String hour) {
        LocalDateTime start = LocalDateTime.parse(hour + ":00:00",
                DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
        LocalDateTime end = start.plusHours(1);

        // selectEnabledPoints 联表 energy_meter，带出 mediaId、deptId
        List<EnergyPoint> points = pointMapper.selectEnabledPoints();
        for (EnergyPoint point : points) {
            TimeSeriesSummary summary = timeSeriesQueryDao.summarize(
                    point.getPointCode(), start, end);

            BigDecimal value;
            if ("CUMULATIVE".equals(point.getPointType())) {
                value = summary.getLastValue().subtract(summary.getFirstValue());
            } else {
                value = summary.getAvgValue();
            }

            EnergyStat stat = new EnergyStat();
            stat.setStatType("HOUR");
            stat.setStatTime(Timestamp.valueOf(start));
            stat.setPointId(point.getPointId());
            stat.setMeterId(point.getMeterId());
            stat.setMediaId(point.getMediaId());
            stat.setDeptId(point.getDeptId());
            stat.setValue(value);
            stat.setUnit(point.getUnit());
            stat.setDataCount(summary.getCount());
            stat.setExpectedCount(60 * 60 / Math.max(point.getPeriodSec(), 1));
            stat.setQuality(summary.getCount() >= stat.getExpectedCount() * 0.98 ? 0 : 1);
            statMapper.upsert(stat);
        }
    }
}
```

### 6.3 跨零点与补数

- 日统计按 `00:00:00` 到次日 `00:00:00`，不要用 `23:59:59`，否则会漏最后一秒。
- 累计量跨零点：取前一天最后一条和后一天第一条的差值，或直接用日末累计值减日初累计值。
- 缺数：先用前后值插值，标记质量码 1；无法插值的标记 2，报表里单独说明。
- 补跑：统计任务要支持传入日期重跑，且结果幂等。

### 7.2 核算服务

```java
@Service
public class CarbonAccountingServiceImpl implements ICarbonAccountingService {

    @Autowired
    private CarbonAccountingMapper accountingMapper;
    @Autowired
    private CarbonEmissionMapper emissionMapper;
    @Autowired
    private CarbonFactorMapper factorMapper;
    @Autowired
    private EnergyStatMapper statMapper;

    private final Map<String, EmissionCalculator> calculatorMap;

    public CarbonAccountingServiceImpl(List<EmissionCalculator> calculators) {
        this.calculatorMap = calculators.stream()
                .collect(Collectors.toMap(EmissionCalculator::sourceType, Function.identity()));
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void calculate(Long accountingId) {
        CarbonAccounting accounting = accountingMapper.selectById(accountingId);
        if (accounting == null) {
            throw new ServiceException("核算任务不存在");
        }
        if ("LOCKED".equals(accounting.getStatus())) {
            throw new ServiceException("已锁定的核算任务不能重算");
        }

        List<CarbonEmission> items = emissionMapper.selectByAccountingId(accountingId);
        BigDecimal scope1 = BigDecimal.ZERO;
        BigDecimal scope2 = BigDecimal.ZERO;
        BigDecimal scope3 = BigDecimal.ZERO;

        for (CarbonEmission item : items) {
            CarbonFactor factor = factorMapper.selectEffective(
                    item.getSourceType(),
                    "NATIONAL",
                    accounting.getPeriodEnd());
            if (factor == null) {
                throw new ServiceException("未找到有效排放因子：" + item.getSourceType());
            }

            EmissionContext context = new EmissionContext();
            context.setActivity(item.getActivityValue());
            context.setFactorValue(factor.getFactorValue());
            context.setSourceType(item.getSourceType());

            EmissionCalculator calculator = calculatorMap.get(item.getSourceType());
            if (calculator == null) {
                throw new ServiceException("不支持的排放源类型：" + item.getSourceType());
            }
            BigDecimal emission = calculator.calculate(context);

            item.setFactorId(factor.getFactorId());
            item.setFactorValue(factor.getFactorValue());
            item.setFactorUnit(factor.getUnit());
            item.setFactorVersion(factor.getVersion());
            item.setEmission(emission);
            emissionMapper.updateById(item);

            if ("SCOPE_1".equals(item.getScope())) {
                scope1 = scope1.add(emission);
            } else if ("SCOPE_2".equals(item.getScope())) {
                scope2 = scope2.add(emission);
            } else {
                scope3 = scope3.add(emission);
            }
        }

        accounting.setScope1(scope1);
        accounting.setScope2(scope2);
        accounting.setScope3(scope3);
        accounting.setTotalEmission(scope1.add(scope2).add(scope3));
        accounting.setStatus("REVIEWED");
        accounting.setCalcTime(new Date());
        accountingMapper.updateById(accounting);
    }
}
```

<Aside type="warning" title="核算结果要保存快照">
  上面把因子值、因子版本写进了 `carbon_emission`，这是最低要求。更严谨的做法是把活动数据、计算公式、数据来源、操作人、时间戳都存成 JSON 快照，锁定后不可变。否则因子升级或统计重跑后，历史报告无法复现。
</Aside>

### 7.3 活动数据从哪来

| 排放源 | 活动数据 | 来源 |
| --- | --- | --- |
| 外购电 | kWh | `energy_stat` 月累计，介质 electricity |
| 天然气 | Nm³ | `energy_stat` 月累计，介质 gas |
| 蒸汽 | GJ/t | 流量计累计 + 焓值换算 |
| 制冷剂 | kg | 手工台账/采购记录 |
| 车辆燃油 | L | 加油卡/台账 |

建议做一个“活动数据汇总”中间表或视图，把不同来源统一成 `source_type + activity_value + unit`，再喂给核算引擎。不要让核算服务直接查十几张业务表。

### 11.2 联调顺序

<Steps>
  <Step title="先通 MQTT">
    MQTTX 能连上 EMQX，Collector 能收到消息并打日志。
  </Step>

  </Step>

  </Step>
  <Step title="再通统计">

  </Step>
  <Step title="最后通碳核算">

  </Step>
</Steps>

### 11.3 常见问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 Mapper 找不到 | 包路径不在扫描范围 | 检查 `@MapperScan` 和 `mapperLocations` |
| 代码生成页面 404 | 前端路由/菜单没配 | 检查菜单 `component` 路径 |
| TDengine 连接超时 | 端口 6030 未开放/驱动版本不匹配 | 用 CLI 先验证，再查 JDBC URL |
| MQTT 一直重连 | ClientId 冲突/账号 ACL | 换 ClientId，查 EMQX 日志 |
| 数据重复 | QoS 1 重发/补传没去重 | 用 `gatewayId + seq` 或时间戳去重 |
| 统计值翻倍 | 任务重复执行/唯一键失效 | 检查 `uk_stat` 和 upsert |
| 碳核算结果与 Excel 不一致 | 单位/因子/口径不同 | 逐步对比活动数据和因子 |
| 页面图表空白 | 容器高度为 0/数据为空 | 给容器固定高度，检查接口返回 |

## 12. 开发顺序建议

| 顺序 | 任务 | 产出 |
| --- | --- | --- |
| 1 | 若依跑通、建库、建模块 | 能登录、能访问业务菜单 |
| 2 | 建介质、计量点、点位表 | 基础数据可维护 |
| 3 | MQTTX → Collector → TDengine | 一条模拟数据入库 |
| 4 | Redis 最新值 + 监控页 | 页面能看到实时值 |
| 5 | 小时/日统计 | 趋势图有数据 |
| 6 | 报警规则 + 报警页 | 超限能触发 |
| 7 | 碳因子 + 核算任务 | 能算出总排放 |
| 8 | 报表导出 + 权限 | 能交付试用 |
| 9 | 接真实仪表 | 数据与现场一致 |

<Aside type="tip" title="先做一条闭环">
  不要同时接电、水、气、汽。先把“一块电表 → 网关 → MQTT → 时序库 → 页面 → 日报 → 碳核算”这条闭环跑通，再复制到其他介质。第一条闭环会暴露 80% 的设计问题。
</Aside>

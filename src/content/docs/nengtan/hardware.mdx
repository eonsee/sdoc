这一章是给“没碰过硬件”的开发者写的。目标不是让你成为电工，而是让你能做到四件事：

1. 看懂现场有哪些表、各自输出什么信号。
2. 画出一条从仪表到平台的完整链路。
3. 写出施工队能照着做、软件能照着解析的**点位表**。
4. 在调试和验收时，判断问题出在仪表、线路、网关还是平台。

<Aside type="danger" title="先说不做的事">
  电表、互感器、配电柜的安装涉及 220V/380V 强电。**不要自己带电接线，不要自己打开配电柜，不要用万用表去测不确定的强电点。** 本章的接线图用于理解原理和验收施工，具体施工必须由持证电工按厂家图纸和当地规范执行。
</Aside>

## 1. 一张图看懂硬件链路

```text
┌─────────────────────────────────────────────────────────────┐
│ 现场层：仪表和设备                                           │
│ 智能电表 · 水表 · 燃气表 · 蒸汽流量计 · 压缩空气流量计 · PLC  │
└───────────────┬─────────────────────────────────────────────┘
                │ ① 信号：RS-485 / 4-20mA / 脉冲 / 以太网
┌───────────────▼─────────────────────────────────────────────┐
│ 采集层：把信号变成数据                                       │
│ 串口服务器 · IO 采集模块 · 4G DTU · 边缘网关 · PLC           │
└───────────────┬─────────────────────────────────────────────┘
                │ ② 传输：以太网 / 4G / 光纤 / LoRa
┌───────────────▼─────────────────────────────────────────────┐
│ 接入层：协议转换与消息分发                                   │
│ 边缘网关（Modbus→MQTT） · EMQX                              │
└───────────────┬─────────────────────────────────────────────┘
                │ ③ 消息：MQTT
┌───────────────▼─────────────────────────────────────────────┐
│ 平台层：采集服务 → 时序库 / 业务库 → 页面                     │
└─────────────────────────────────────────────────────────────┘
```

用一个类比：

- **仪表**是眼睛，负责“看见”用了多少电、多少水。
- **采集层**是翻译官兼邮差，把仪表的话翻译成平台能懂的语言，再送出去。
- **平台**是大脑，负责存储、统计、报警和核算。

你不需要会造眼睛，但必须知道眼睛看的是什么、说的是什么语言、邮差走哪条路。

## 2. 零基础必须懂的十个概念

### 2.1 模拟量：4-20mA 和 0-10V

传感器把物理量（压力、流量、温度）变成连续变化的电信号。

| 信号 | 含义 | 常见场景 |
| --- | --- | --- |
| 4-20mA | 4mA 对应量程下限，20mA 对应上限 | 压力变送器、流量计、液位计 |
| 0-10V | 0V 对应下限，10V 对应上限 | 部分温湿度传感器、变频器 |
| 0-5V | 同上，量程不同 | 老设备、实验设备 |

为什么工业上偏爱 4-20mA：

- 电流信号抗干扰能力强，长距离传输衰减小。
- 4mA 作为“活零点”，可以区分“信号为 0”和“断线”（断线时电流为 0mA）。
- 两线制变送器可以靠这两根线同时供电和传信号。

<Aside type="note" title="接线要点">
  两线制 4-20mA 变送器通常串联在 24V 直流回路里，采集端用一个采样电阻（常见 250Ω）把电流转成 1-5V 电压。接线前确认变送器是两线制、三线制还是四线制，接错可能烧坏。
</Aside>

### 2.2 开关量：干接点

只有“通”和“断”两种状态，例如：

- 设备运行/停止
- 阀门开/关
- 柜门开/关
- 报警触点

“干接点”指不带电的触点，需要采集模块提供电源（湿接点则自带电压）。软件上就是一个 0/1 布尔值。

### 2.3 脉冲量

仪表每计量一定量，就输出一个脉冲。例如水表每 0.1 立方米发一个脉冲，电表每 1 kWh 发一个脉冲。

软件要做两件事：

- **计数**：累计脉冲数。
- **换算**：累计量 = 脉冲数 × 脉冲当量。

脉冲量的坑很多：抖动、丢脉冲、脉冲宽度太窄、上拉电阻缺失。后面会细讲。

### 2.4 RS-485 和 RS-232

| 项目 | RS-485 | RS-232 |
| --- | --- | --- |
| 信号方式 | 差分，A/B 两根线 | 单端，TX/RX/GND |
| 传输距离 | 理论 1200 米（低速率） | 约 15 米 |
| 拓扑 | 总线手拉手，可挂多台 | 点对点 |
| 抗干扰 | 强 | 弱 |
| 工业现场 | **最常用** | 少见，多用于调试 |

RS-485 是电表、水表、流量计最常见的通信接口。它只规定电气层，不规定“说什么语言”——上面跑什么协议，取决于仪表支持 Modbus、DL/T 645 还是厂家私有协议。

### 2.5 Modbus RTU 和 Modbus TCP

Modbus 是工业界最通用的应用层协议。

- **Modbus RTU**：跑在 RS-485/RS-232 上，二进制帧，带 CRC 校验。
- **Modbus TCP**：跑在以太网上，帧里去掉 CRC，加一个 MBAP 头，默认端口 502。

一帧 Modbus RTU 长这样：

```text
┌────────┬──────────┬──────────────┬─────────┐
│ 从站地址│ 功能码    │ 数据          │ CRC16   │
│ 1 字节  │ 1 字节    │ N 字节        │ 2 字节  │
└────────┴──────────┴──────────────┴─────────┘
```

### 2.6 从站地址、寄存器、功能码

这三个词会贯穿整个采集过程。

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 从站地址 | 总线上每台表的编号 | 1～247，不能重复 |
| 寄存器 | 表内部存放数据的位置 | 0x0000 存 A 相电压 |
| 功能码 | 你要做什么操作 | 03 读保持寄存器，04 读输入寄存器 |

常用功能码：

| 功能码 | 名称 | 用途 |
| --- | --- | --- |
| 01 (0x01) | 读线圈 | 读开关量输出状态 |
| 02 (0x02) | 读离散输入 | 读开关量输入状态 |
| 03 (0x03) | 读保持寄存器 | **最常用**，读测量值、参数 |
| 04 (0x04) | 读输入寄存器 | 读只读测量值 |
| 05 (0x05) | 写单个线圈 | 控制开关 |
| 06 (0x06) | 写单个寄存器 | 改参数 |
| 15 (0x0F) | 写多个线圈 | 批量控制 |
| 16 (0x10) | 写多个寄存器 | 批量改参数 |

<Aside type="caution" title="地址基准是最常见的坑">
  仪表手册写“40001”，协议里可能要从 0 开始算，实际发的是 `0x0000`；也可能手册直接给 `0x0000`。不同厂家习惯不同，必须用调试工具试读确认。**不要凭猜写点位表。**
</Aside>

### 2.7 波特率、数据位、停止位、校验位

串口通信前，双方必须约定相同的“说话速度”和“格式”。

| 参数 | 常见值 | 说明 |
| --- | --- | --- |
| 波特率 | 2400、4800、9600、19200、38400、115200 | 电表常见 2400/9600 |
| 数据位 | 8 | 几乎都是 8 |
| 停止位 | 1 | 少数 2 |
| 校验位 | 无（N）、偶（E）、奇（O） | DL/T 645 常用偶校验 |

常见组合写作 `9600 8N1`，表示 9600 波特、8 数据位、无校验、1 停止位。

如果波特率或校验位不对，表现通常是：**完全收不到数据，或收到乱码**。先核对这两项，再查接线。

### 2.8 网关、DTU、串口服务器

| 设备 | 做什么 | 典型场景 |
| --- | --- | --- |
| 串口服务器 | 把 RS-485/RS-232 转成以太网 TCP | 车间有网线，电表集中 |
| DTU | 把串口数据通过 4G/5G 发到平台 | 现场没网线，点位分散 |
| 边缘网关 | 多协议接入、协议转换、本地缓存、规则计算 | 多品牌仪表、需要离线缓存 |
| IO 采集模块 | 把 4-20mA、脉冲、开关量转成 Modbus | 仪表没有 RS-485 |
| PLC | 现场控制 + 数据采集 | 已有自动化系统 |

### 2.9 常见协议

| 协议 | 主要用途 | 你需要知道什么 |
| --- | --- | --- |
| Modbus RTU/TCP | 电表、水表、流量计、PLC | 地址、功能码、寄存器、数据类型 |
| DL/T 645-2007 | 国内电能表 | 表地址、数据标识、波特率、校验位 |
| IEC 60870-5-104 | 电力综自、变电站 | 点表、遥测遥信、端口 2404 |
| OPC UA | PLC、DCS、上位机 | Endpoint、节点 ID、安全策略 |
| BACnet/IP | 楼宇空调、暖通 | 对象类型、实例号、端口 47808 |
| Siemens S7 | 西门子 PLC | 机架、槽号、DB 块地址 |
| MQTT | 网关上行到平台 | Topic、QoS、ClientId、鉴权 |

### 2.10 采集周期、心跳、离线缓存

| 概念 | 作用 | 建议 |
| --- | --- | --- |
| 采集周期 | 多久读一次表 | 电表 15 秒～1 分钟；水气汽 1～5 分钟 |
| 心跳 | 证明网关还活着 | 30～60 秒一次 |
| 离线缓存 | 断网时把数据存本地 | 至少 7 天 |
| 补传 | 网络恢复后补发 | 按时间顺序，去重 |
| 时间同步 | 保证数据时间准确 | NTP，每天同步 |

## 3. 计量点规划

### 3.1 三级计量

```text
一级：园区/厂区总表
   │
   ├── 二级：车间/楼层总表
   │      │
   │      ├── 三级：产线/重点设备表
   │      └── 三级：产线/重点设备表
   │
   └── 二级：车间/楼层总表
```

规划原则：

- **总表必须覆盖分表**：一级总表 ≥ 二级分表之和，差额是线损、变压器损耗、公共用电。
- **重点设备单独计量**：空压机、中央空调、锅炉、注塑机、熔炉等。
- **留 10%～20% 备用点位**：后期加表不用重新拉总线。
- **总表和分表尽量同一时段采集**：否则对账时时间不同步，永远对不上。

### 3.2 命名规范

建议用“位置 + 介质 + 序号”的编码，全系统唯一、可读、可排序：

```text
{园区}-{区域}-{介质}-{序号}

SH01-C01-ELE-001     上海园区-1号车间-电-001
SH01-C01-WAT-001     上海园区-1号车间-水-001
SH01-C02-GAS-001     上海园区-2号车间-天然气-001
SH01-C03-STM-001     上海园区-3号车间-蒸汽-001
SH01-C04-AIR-001     上海园区-4号车间-压缩空气-001
```

点位编码在计量点编码后加后缀：

```text
SH01-C01-ELE-001.EP    正向有功电能
SH01-C01-ELE-001.P     有功功率
SH01-C01-ELE-001.UA    A 相电压
SH01-C01-WAT-001.V     累计流量
```

### 3.3 计量点清单

在写代码之前，先填完这张表，让甲方或厂务签字确认：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 计量点编码 | 全系统唯一 | `SH01-C01-ELE-001` |
| 计量点名称 | 人能看懂 | 1 号车间总进线 |
| 所属组织 | 园区/车间/产线 | 上海园区/1 号车间 |
| 能源介质 | 电/水/气/汽/压缩空气 | 电 |
| 计量层级 | 一级/二级/三级 | 二级 |
| 安装位置 | 配电柜编号/管道位置 | 1 号车间配电柜 AP-01 |
| 仪表品牌型号 | 便于采购和备件 | 某品牌 DTSD1352 |
| 仪表编号 | 出厂序列号 | 2026xxxx |
| 通信方式 | RS-485/4-20mA/脉冲/以太网 | RS-485 |
| 协议 | Modbus RTU/DL/T 645 | Modbus RTU |
| 从站地址 | 1～247 | 3 |
| 波特率/校验 | 9600 8N1 | 9600 8N1 |
| 倍率 | CT/PT 变比 | 80 |
| 采集周期 | 秒 | 60 |
| 是否考核 | 是否纳入定额 | 是 |
| 备注 | 施工注意 | 与 2 号表共用总线 |

### 3.4 精度等级怎么选

| 用途 | 建议精度 | 说明 |
| --- | --- | --- |
| 贸易结算、与电网对账 | 0.2S 或 0.5S | 电能计量，需检定 |
| 内部车间考核 | 0.5S 或 1.0 | 兼顾成本和准确度 |
| 一般监测、趋势分析 | 1.0 或 2.0 | 不需要太高的绝对精度 |
| 碳核算 | 至少 1.0，关键边界 0.5S | 取决于核算指南和核查要求 |

<Aside type="caution" title="碳核算对数据的要求">
  如果碳核算结果要用于对外报告或第三方核查，活动数据的计量器具需要满足相应的检定/校准要求，数据要能追溯。不要用“估算值”冒充“计量值”，也不要把没有检定的表当作结算依据。
</Aside>

## 4. 电计量：电表、互感器、接线

电是能碳系统里最重要的介质，也是接线最容易出问题的部分。

### 4.1 电表类型

| 类型 | 特点 | 适用 |
| --- | --- | --- |
| 单相电表 | 220V，一路火线零线 | 办公、照明、小功率设备 |
| 三相四线电表 | 3×220/380V，三火一零 | 大多数车间、设备 |
| 三相三线电表 | 3×380V，三火 | 部分高压/工业场合 |
| 直接接入式 | 电流直接过表，常见 10(60)A、20(80)A | 小负荷 |
| 互感器接入式 | 经 CT 接入，常见 1.5(6)A | 大负荷 |
| 导轨式 | 体积小，装在配电箱导轨上 | 分项计量、改造项目 |
| 多功能表 | 电压、电流、功率、电能、功率因数、谐波 | 能碳系统首选 |

### 4.2 选型关键参数

买表前至少确认这八项：

| 参数 | 常见值 | 说明 |
| --- | --- | --- |
| 电压规格 | 3×220/380V | 与现场供电制式一致 |
| 电流规格 | 3×1.5(6)A 或 3×10(100)A | 经 CT 还是直接接入 |
| 精度 | 0.5S / 1.0 | S 级用于计量 |
| 通信接口 | RS-485 | 最好双接口或支持蓝牙调试 |
| 通信协议 | Modbus-RTU / DL/T 645 | 确认平台能解析 |
| 脉冲输出 | 有功/无功脉冲 | 用于校验 |
| 辅助电源 | 220V AC 或 85-265V | 断电后通信是否保持 |
| 安装方式 | 导轨/壁挂/嵌入式 | 配电柜空间 |

<Aside type="tip" title="优先选同时支持 Modbus 和 DL/T 645 的表">
  现场调试时，如果一种协议读不通，可以换另一种验证。平台侧也更容易做兼容。注意：同一块表通常只能同时启用一种协议，具体看说明书。
</Aside>

### 4.3 电流互感器（CT）

当负荷电流超过电表直接接入能力时，要用电流互感器把大电流按比例缩小。

**变比**：例如 `400/5`，表示一次侧 400A 时，二次侧输出 5A。变比 = 400 ÷ 5 = 80。

**精度**：计量用 `0.5S` 或 `0.2S`；一般监测可用 `0.5` 或 `1.0`。S 级在低负荷下也能保证精度。

**容量**：CT 的额定负载（VA）要大于二次回路实际负载，否则精度下降。二次线越长、越细，负载越大。

**穿心方向**：CT 上标有 `P1`、`P2`。电流从 P1 流向 P2 时，二次侧 S1、S2 的输出方向是确定的。穿反了，功率和电量可能为负或少计。

**二次侧绝对不能开路**：CT 二次侧在带电状态下开路，会产生危险的高电压。拆表或换表前，必须先用短接片把 S1、S2 短接。

**接地**：CT 二次侧通常要求一点接地，按当地规范和厂家要求执行。不要多点接地形成环流。

```text
CT 穿心示意（以 P1→P2 为例）

  母线/电缆 ────▶ P1 ──[ CT ]── P2 ────▶ 负载
                              │
                          S1 ─┴─ S2
                           │     │
                        电表 IA+ IA-
```

<Aside type="danger" title="拆 CT 二次线前必须短接">
  带电状态下打开 CT 二次回路，二次侧可能感应出数千伏高压，足以致命。任何涉及 CT 二次回路的操作，必须停电、验电，并由持证电工执行。
</Aside>

### 4.4 三相四线经 CT 接入的接线概念

下面是最简化的概念图，**实际端子号以电表说明书为准**：

```text
三相四线，3 只 CT，经互感器接入

L1 ── P1 [CT1] P2 ── 负载
        S1 ──────── 电表 IA+
        S2 ──────── 电表 IA-

L2 ── P1 [CT2] P2 ── 负载
        S1 ──────── 电表 IB+
        S2 ──────── 电表 IB-

L3 ── P1 [CT3] P2 ── 负载
        S1 ──────── 电表 IC+
        S2 ──────── 电表 IC-

L1 ──────────────── 电表 UA
L2 ──────────────── 电表 UB
L3 ──────────────── 电表 UC
N  ──────────────── 电表 UN

电表辅助电源：220V AC（L/N）
电表 RS-485：A/B 接总线
```

实际接线还要考虑：

- 电压采样是否经过熔断器/空开。
- 电表电压端子是否与电流端子分开。
- 是否需要试验接线盒，方便校验和短接。
- 屏蔽线的屏蔽层怎么接地。
- 相序是否一致。

### 4.5 倍率：最容易算错的一步

如果电表显示的是二次侧电量，实际电量要乘倍率：

```text
实际电量 = 电表读数差 × CT 变比 × PT 变比
```

示例：CT 变比 400/5 = 80，PT 变比 1（低压没有 PT），电表读数从 1000.00 到 1050.00，差 50 kWh：

```text
实际电量 = 50 × 80 × 1 = 4000 kWh
```

<Aside type="warning" title="先确认电表显示的是二次值还是已经乘过倍率">
  有些电表允许在参数里设置 CT/PT 变比，显示的就是一次侧实际值；有些表只显示二次值，需要平台乘倍率。**同一个项目里两种表混用，是电量对不上的常见原因。** 点位表里必须有一列“倍率”，并注明“表内已乘”还是“平台乘”。
</Aside>

### 4.6 电表接线常见错误

| 错误 | 现象 | 后果 |
| --- | --- | --- |
| CT 穿反 | 有功功率为负、电量为负 | 少计或计量方向错误 |
| 只穿两相 | 三相不平衡、功率偏低 | 少计 |
| 电压缺相 | 某相电压为 0 | 少计 |
| 相序接错 | 功率因数异常、功率偏低 | 计量不准 |
| CT 二次开路 | 无读数、端子打火 | 危险，可能损坏设备 |
| 倍率没乘 | 电量偏小 80 倍 | 严重少计 |
| 电表常数设错 | 脉冲计数偏差 | 电量偏差 |
| 通信地址重复 | 总线上多块表冲突 | 通信时好时坏 |
| A/B 接反 | 完全通信不上 | 需要调换 |
| 屏蔽层两端接地 | 环流、干扰 | 数据跳变 |

## 5. 水、天然气、蒸汽、压缩空气

### 5.1 水表

常见类型：

| 类型 | 输出 | 特点 |
| --- | --- | --- |
| 机械水表 + 脉冲 | 干接点脉冲 | 便宜，需计数 |
| 光电直读水表 | RS-485/M-Bus | 直接读字轮，不怕断电 |
| 电磁流量计 | 4-20mA/RS-485/脉冲 | 精度高，要求满管 |
| 超声波水表 | RS-485/脉冲 | 无阻流件，精度高 |

**脉冲水表接线**：

```text
水表脉冲输出（干接点）
     │
     ├──── 采集模块 DI+
     │
     └──── 采集模块 DI-
```

如果是无源干接点，采集模块需要提供上拉电源；如果是 NPN/PNP 输出，要确认极性。常见做法是加 10kΩ 上拉电阻和 RC 消抖，软件再做 20～50ms 的防抖。

**脉冲当量**：看水表铭牌，例如 `1 脉冲 = 0.1 m³` 或 `1 脉冲 = 1 L`。软件累计量 = 脉冲数 × 当量。

**常见坑**：

- 脉冲太窄，采集模块扫不到。
- 没有上拉电阻，信号一直是低电平。
- 软件防抖时间太长，快速流时丢脉冲。
- 水表倒流，脉冲仍然计数。
- 脉冲当量和表盘倍率不一致。

### 5.2 天然气

常见表型：膜式燃气表、罗茨流量计、涡轮流量计、涡街流量计、超声波流量计。

**工况 vs 标况**：燃气表测的是工况体积（实际温度和压力下的体积），碳核算和贸易结算通常要换算到标准状态。

近似换算：

```text
Q_n = Q_w × (P_w ÷ P_n) × (T_n ÷ T_w)
```

其中：

- `Q_n`：标况体积流量
- `Q_w`：工况体积流量
- `P_w`：工况绝对压力
- `P_n`：标准大气压（101.325 kPa）
- `T_n`：标准温度（开尔文，常用 293.15K 即 20℃）
- `T_w`：工况绝对温度

更精确的换算要考虑压缩因子 `Z`，高压场合必须用。

**安全**：燃气场合必须用防爆型仪表和采集设备，安装燃气泄漏报警，动火作业要审批。不要在没有防爆认证的设备上接线。

### 5.3 蒸汽

蒸汽计量通常用涡街流量计、孔板流量计或平衡流量计，并配温度、压力补偿。

**为什么需要补偿**：蒸汽的体积随温度和压力变化很大，只有体积流量无法直接算质量或热量。

```text
质量流量 = 体积流量 × 工况密度
```

- 饱和蒸汽：根据压力或温度查密度表。
- 过热蒸汽：根据温度和压力查密度（可用 IAPWS-IF97 公式）。

**安装要点**：

- 直管段：涡街常见要求上游 15D、下游 5D（D 为管径），以厂家手册为准。
- 管道必须满管，不能有积液或气泡。
- 变送器引压管要有冷凝弯，防止高温蒸汽直接损坏变送器。
- 管道保温，但流量计本体按厂家要求处理。
- 蒸汽高温高压，安装和检修必须由专业人员执行。

### 5.4 压缩空气

常用涡街流量计或热式质量流量计，单位常见 `Nm³/min` 或 `m³/h`。

能碳系统里常看三个指标：

| 指标 | 计算 | 用途 |
| --- | --- | --- |
| 瞬时流量 | 表计直读 | 监控用气 |
| 累计用量 | 积分或累计寄存器 | 成本分摊 |
| 比功率 | 空压机功率 ÷ 排气量，kW/(m³/min) | 能效评估 |
| 泄漏率 | 非生产时段基础流量 ÷ 平均流量 | 跑冒滴漏 |

<Aside type="note" title="标况定义要统一">
  不同厂家对“标况”的定义可能是 0℃ 或 20℃，也可能是 101.325 kPa 或其他基准。点位表和报表里必须写明基准，否则同一个数会有几 percent 的差异。
</Aside>

### 5.5 冷/热量表

热量表通常输出瞬时热量、累计热量、瞬时流量、进/回水温度。注意：

- 供回水温度传感器要成对匹配。
- 累计热量单位常见 kWh 或 GJ，换算关系 `1 GJ = 277.78 kWh`。
- 冬季防冻、夏季制冷工况的符号可能不同。

### 5.6 生产数据

碳强度和单位产品能耗离不开产量。常见来源：

- PLC 计数器（产量脉冲）。
- MES/ERP 接口（班次产量、产值）。
- 手工填报（小企业现实做法）。

第一版可以做成“手工填报 + 审核”，不要为了自动化去改生产线。

## 6. 采集方案选型

### 6.1 六种典型方案

| 方案 | 链路 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| A. RS-485 + 串口服务器 | 表 → 总线 → 串口服务器 → 以太网 | 稳定、便宜、易维护 | 需要布线 | 车间电表集中、有网线 |
| B. 4G DTU | 表 → DTU → 4G → 平台 | 无需布线、部署快 | 每台一张卡、流量费 | 分散点位、无网 |
| C. PLC + OPC UA | 表/设备 → PLC → OPC UA → 网关 | 复用自动化系统 | 受 PLC 品牌限制 | 已有 PLC 的产线 |
| D. IO 采集模块 | 4-20mA/脉冲 → IO 模块 → RS-485 | 兼容老仪表 | 点位少、需要布线 | 无通信接口的仪表 |
| E. LoRa/NB-IoT | 表 → 无线模块 → 网关 → 平台 | 免布线、电池供电 | 带宽低、时延大 | 水表、燃气表分散 |
| F. 边缘网关 | 多协议 → 网关 → MQTT | 协议全、可缓存、可算 | 价格高、配置复杂 | 多品牌、多协议 |

### 6.2 方案 A：RS-485 总线 + 串口服务器

这是最推荐的车间方案。

```text
电表1 ──┐
电表2 ──┤
电表3 ──┼── RS-485 总线 ── 串口服务器 ── 交换机 ── 边缘网关/平台
...     │
电表N ──┘
```

要点：

- 手拉手串联，不要星型分支。
- 总线两端各接一个 120Ω 终端电阻。
- 使用双绞屏蔽线，屏蔽层单端接地。
- 每段总线建议不超过 32 台表；超过就分端口或加中继器。
- 总线远离动力电缆，交叉时垂直交叉。

**轮询时间估算**：

```text
单表耗时 ≈ (请求字节数 + 响应字节数) × 10 ÷ 波特率 + 表处理延时
```

以 9600 8N1、每表读 10 个寄存器（请求 8 字节、响应 25 字节）、表处理延时 50ms 为例：

```text
(8 + 25) × 10 ÷ 9600 ≈ 0.034 秒
0.034 + 0.05 ≈ 0.084 秒/表
32 台表 ≈ 2.7 秒/轮
```

一分钟采一轮绰绰有余。如果表很多、点位很多，就把采集周期放宽或分总线。

### 6.3 方案 B：4G DTU

适合没有网线、点位分散的场景。

```text
电表 ── RS-485 ── 4G DTU ── 基站 ── 互联网 ── EMQX
```

要点：

- 每台 DTU 需要 SIM 卡和流量套餐。
- 配 APN、服务器地址、端口、ClientId、用户名密码。
- 建议 DTU 主动连接平台，不要让平台反向连 DTU。
- 断网缓存和补传能力要看 DTU 型号，便宜的可能没有。
- 天线放在信号好的位置，金属柜内要外置天线。

### 6.4 方案 C：PLC + OPC UA

如果产线已有 PLC，优先从 PLC 取数据，而不是重复加表。

```text
设备 ── PLC ── OPC UA / Modbus TCP ── 边缘网关 ── MQTT
```

要点：

- 需要 PLC 工程师提供变量表（DB 块、偏移、数据类型）。
- OPC UA 要确认 Endpoint、安全策略、用户名密码。
- 西门子 S7-1200/1500 需要开启 PUT/GET 或 OPC UA 服务。
- 不要直接改 PLC 程序，除非有变更审批和备份。

### 6.5 方案 D：IO 采集模块

适合只有 4-20mA、0-10V、脉冲或开关量的老仪表。

```text
流量计 4-20mA ── IO 模块 AI 通道 ── RS-485 ── 网关
水表脉冲     ── IO 模块 DI 通道 ── RS-485 ── 网关
```

选型要点：

- 通道数：8 路 AI、8 路 DI 常见。
- 输入类型：4-20mA、0-10V、干接点。
- 分辨率：12 位以上。
- 隔离：通道间隔离更好，抗干扰。
- 通信：Modbus RTU，地址和波特率可设。

### 6.6 方案 E：LoRa / NB-IoT

| 技术 | 特点 | 适用 |
| --- | --- | --- |
| LoRa | 自建网关，免流量费，距离几百米到几公里 | 园区内水表、燃气表 |
| NB-IoT | 运营商网络，电池寿命长，时延较高 | 分散的远传水表、燃气表 |
| 4G Cat.1 | 带宽和成本平衡 | 需要较高频率上报的设备 |

注意：LoRa 在中国常用 470MHz 频段，网关容量和上报频率受限于占空比和网络规划；NB-IoT 需要运营商支持，数据要经过运营商平台。

### 6.7 方案 F：边缘网关

边缘网关适合“多协议 + 本地逻辑”的场景：

- 同时接 Modbus RTU、Modbus TCP、OPC UA、DL/T 645。
- 本地做点位映射、单位换算、越限判断。
- 断网缓存 7 天，恢复后补传。
- 通过 MQTT 上行，支持远程配置。

选型时重点看：协议数量、点位容量、缓存容量、是否支持脚本、远程升级、看门狗、工作温度、防护等级。

## 7. 通信与网络

### 7.1 RS-485 布线规范

| 项目 | 要求 |
| --- | --- |
| 线缆 | 双绞屏蔽线，0.5mm² 左右 |
| 拓扑 | 手拉手，禁止星型、禁止长分支 |
| 终端电阻 | 总线两端各 120Ω |
| 节点数 | 标准 32 台，低功耗收发器可更多 |
| 距离 | 9600 波特率下可达 1200 米 |
| 屏蔽层 | 单端接地，通常接在控制柜侧 |
| 走线 | 远离动力电缆，间距至少 200mm，交叉时垂直 |
| 接地 | 现场地电位差大时用隔离型收发器 |

<Aside type="tip" title="A/B 线序不要死记">
  不同厂家对 A/B 的定义可能相反。通信不上时，先断电，把 A/B 对调试一次。这是现场最快的方法，但要在断电状态下操作。
</Aside>

### 7.2 以太网

- 使用工业交换机，不要用家用路由器凑合。
- 网线单段不超过 100 米，超长用光纤。
- 给仪表、网关、服务器规划不同网段，例如：

| 设备 | 网段示例 |
| --- | --- |
| 现场仪表/串口服务器 | 192.168.10.0/24 |
| 边缘网关 | 192.168.20.0/24 |
| 服务器 | 10.0.0.0/24 |
| 办公网 | 172.16.0.0/16 |

- 用 VLAN 把 OT（生产）和 IT（办公）隔开。
- 只开放必要端口：Modbus TCP 502、OPC UA 4840、MQTT 1883/8883、HTTPS 443。
- 现场设备不要配公网 IP。

### 7.3 无线

| 技术 | 频段/网络 | 距离 | 适用 |
| --- | --- | --- | --- |
| WiFi | 2.4/5GHz | 几十米 | 室内、有 AP |
| 4G/5G | 运营商 | 覆盖范围内 | 分散、无网线 |
| LoRa | 470MHz（中国） | 几百米～几公里 | 园区低功耗表计 |
| NB-IoT | 运营商 | 覆盖范围内 | 电池供电、低频上报 |

无线方案一定要做**信号测试**：把网关和表装在最终位置，测信号强度和丢包率，不要只在办公室测。

### 7.4 网络隔离

```text
现场仪表/PLC ── 工业交换机 ── 防火墙 ── 服务器
                                  │
                              办公网/互联网
```

原则：

- 现场网络与办公网隔离。
- 只允许采集服务主动访问现场，或现场网关主动连接平台。
- 远程运维走 VPN/堡垒机，不要直接映射端口。
- MQTT 使用 TLS 和账号 ACL，每个网关一个账号。

## 8. 供电、防雷、接地、防护

### 8.1 供电

| 设备 | 供电 | 注意 |
| --- | --- | --- |
| 电表 | 220V AC 或 85-265V | 确认辅助电源是否独立 |
| 水表/流量计 | 24V DC 或电池 | 两线制/四线制 |
| 串口服务器 | 24V DC 或 220V AC | 建议集中 24V 供电 |
| 网关/DTU | 24V DC 或 12V DC | 配电源适配器 |
| 交换机 | 24V DC 或 220V AC | 工业交换机 |

建议：

- 控制柜内用 24V 开关电源集中供电，留 30% 余量。
- 重要网关配 UPS，至少撑 30 分钟。
- 电源线和信号线分开走线。
- 每个回路加空开和保险丝。

### 8.2 防雷与接地

| 措施 | 说明 |
| --- | --- |
| 电源防雷 | 控制柜进线加电源 SPD |
| 信号防雷 | RS-485、4-20mA 加信号 SPD |
| 接地 | 控制柜、屏蔽层、SPD 按规范接地 |
| 接地电阻 | 通常要求 ≤4Ω，按当地规范 |
| 等电位 | 避免不同设备间地电位差 |
| 屏蔽 | 屏蔽层单端接地，不要两端接 |

<Aside type="caution" title="雷击是户外仪表的头号杀手">
  室外水表、燃气表、屋顶设备的信号线最容易引雷。信号 SPD 和良好接地不是可选项。已经发生过雷击的区域，要检查 SPD 是否失效。
</Aside>

### 8.3 防护等级与环境

| 环境 | 建议防护 | 注意 |
| --- | --- | --- |
| 室内配电柜 | IP20～IP54 | 防尘、防触电 |
| 车间潮湿/粉尘 | IP65 | 防水防尘 |
| 室外 | IP65/IP67 | 防雨防晒 |
| 燃气/化工 | 防爆认证 | Ex d/Ex i，按区域选型 |
| 高温 | 看工作温度 | 加散热或远离热源 |
| 强电磁干扰 | 屏蔽、隔离、滤波 | 远离变频器、焊机 |

| `.PF` | 功率因数 | INT16 | 03 | 0x002A | 1 | AB | 0.001 | — | 60 |
| `.F` | 频率 | UINT16 | 03 | 0x002B | 1 | AB | 0.01 | Hz | 60 |
| `.EP` | 正向有功电能 | UINT32 | 03 | 0x0100 | 2 | ABCD | 0.01 | kWh | 60 |

### 9.3 数据类型

| 类型 | 字节 | 范围 | 说明 |
| --- | --- | --- | --- |
| UINT16 | 2 | 0～65535 | 无符号短整型 |
| INT16 | 2 | -32768～32767 | 有符号短整型 |
| UINT32 | 4 | 0～4294967295 | 无符号长整型，占 2 个寄存器 |
| INT32 | 4 | -2147483648～2147483647 | 有符号长整型 |
| FLOAT32 | 4 | IEEE 754 | 单精度浮点，占 2 个寄存器 |
| BCD | — | — | 二进制编码十进制，DL/T 645 常见 |

### 9.4 字节序和字序

Modbus 寄存器是 16 位的。32 位数据占两个寄存器，谁在前谁在后，不同厂家可能不同。

| 字节序 | 含义 | 示例（值 0x12345678） |
| --- | --- | --- |
| ABCD | 高字在前，高字节在前 | 0x1234, 0x5678 |
| CDAB | 低字在前，高字节在前 | 0x5678, 0x1234 |
| BADC | 高字在前，字节交换 | 0x3412, 0x7856 |
| DCBA | 低字在前，字节交换 | 0x7856, 0x3412 |

如果数值明显不对（例如 123.4 读成 0.001 或 1.6e38），先换字序试，而不是怀疑仪表坏了。

### 9.5 缩放、偏移、单位

```text
工程值 = 原始值 × scale + offset
```

示例：原始值 `12345`，`scale = 0.01`，则工程值 `123.45 kWh`。

注意：

- 累计电量可能超过 32 位，读之前确认是否需要 64 位或两个寄存器拼接。
- 有符号数据要按补码解释。
- 单位统一：电 kWh、水 m³、气 Nm³、蒸汽 GJ 或 t、压缩空气 Nm³。
- 时间统一用带时区的时间戳，数据库存 UTC，页面显示 `Asia/Shanghai`。

### 9.6 数据质量码

| 码 | 含义 | 处理 |
| --- | --- | --- |
| 0 | 正常 | 正常使用 |
| 1 | 可疑 | 参与统计但标记 |
| 2 | 异常 | 不参与统计，报警 |
| 3 | 离线 | 用上一有效值或补数 |
| 4 | 人工补录 | 记录操作人 |

### 9.7 网关上报格式

建议用 JSON，字段短但可读：

```json
{
  "gatewayId": "GW-SH01-01",
  "meterCode": "SH01-C01-ELE-001",
  "energyType": "electricity",
  "ts": 1760000000000,
  "seq": 1024,
  "quality": 0,
  "points": {
    "UA": 220.1,
    "UB": 219.8,
    "UC": 220.4,
    "P": 123.4,
    "EP": 45678.9
  }

```

```text

```

<Aside type="tip" title="保留原始报文">
  调试阶段建议把原始报文（十六进制）也存一份，出问题时能复现解析过程。生产环境可以只保留异常报文，避免存储膨胀。
</Aside>

## 10. 采集频率、边缘规则与时间同步

### 10.1 采集频率

| 数据 | 建议周期 | 理由 |
| --- | --- | --- |
| 电参量（电压/电流/功率） | 15～60 秒 | 监控和需量分析 |
| 累计电量 | 60 秒 | 电量变化慢，没必要太快 |
| 水/气/汽累计量 | 1～5 分钟 | 变化慢，节省流量 |
| 温度/压力 | 30～60 秒 | 工艺监控 |
| 报警状态 | 5～15 秒 | 及时性 |
| 设备运行状态 | 15～30 秒 | 停机统计 |

### 10.2 边缘规则

网关或采集服务可以做的事：

- **死区过滤**：变化小于死区不上报，减少数据量。
- **越限判断**：本地判断高限/低限，立即上报事件。
- **需量计算**：15 分钟滑动窗口，计算最大需量。
- **断网缓存**：本地存 7 天，恢复后按时间补传。
- **数据质量标记**：超时、越限、校验失败打质量码。

### 10.3 时间同步

时间不准，统计和碳核算都会出问题。

- 网关和采集服务器都配 NTP。
- 电表支持对时的话，每天对时一次。
- 数据库存 UTC 或带时区的时间戳。
- 页面展示统一用 `Asia/Shanghai`。
- 补传数据要保留原始采集时间，不要用补传时间覆盖。

## 11. 施工与调试：一步一步

<Steps>
  <Step title="现场勘查与安全交底">
    确认计量点位置、配电柜编号、管道位置、取电点、网络路径。和厂务、电工、安全员一起做安全交底，明确停电范围和作业票。
  </Step>
  <Step title="停电、验电、挂牌">
    按作业票停电，验电确认无电，挂“禁止合闸”牌。涉及 CT 二次回路的，先短接。
  </Step>
  <Step title="安装仪表和互感器">
    按厂家图纸安装电表、CT、水表、流量计。注意 CT 的 P1/P2 方向、流量计的直管段和满管要求。
  </Step>
  <Step title="接线与标识">
    按接线图接线，每根线两端贴标签。强电和弱电分开走线，屏蔽层按规范接地。
  </Step>
  <Step title="上电前检查">
    检查是否有短路、开路、接错、螺丝松动。用万用表测电压和通断，确认无误再上电。
  </Step>
  <Step title="设置仪表参数">
    设置从站地址、波特率、校验位、协议、CT/PT 变比、电表常数、时间。每块表单独记录参数。
  </Step>
  <Step title="单表调试">
    用厂家软件、Modbus Poll 或串口助手逐块表读数据。确认地址、寄存器、数据类型、倍率都对。
  </Step>
  <Step title="总线联调">
    把所有表挂上总线，逐台轮询。检查是否有地址冲突、通信超时、数据跳变。
  </Step>
  <Step title="网关与平台对接">
    配置网关的点位映射、MQTT 参数、上报周期。在平台上确认数据入库、时间正确、质量码正常。
  </Step>
  <Step title="数据核对">
    用钳形表、电费单、人工抄表、水表表盘核对。电量偏差应小于 1%，水气偏差按表计精度要求。
  </Step>
  <Step title="试运行与验收">
    连续运行 7 天，检查在线率、数据完整率、报警、断网补传、时间同步。整理竣工图和点位表，签字验收。
  </Step>
</Steps>

## 12. 常见故障排查

| 现象 | 可能原因 | 排查顺序 |
| --- | --- | --- |
| 整条总线都通信不上 | 电源、波特率、A/B 接反、终端电阻、串口服务器 | 先测电源，再对波特率，再换 A/B |
| 单块表通信不上 | 地址冲突、接线松动、表故障、协议不对 | 单独接这块表试读 |
| 数据一直是 0 | 寄存器错、CT 短接、表未运行、倍率错 | 用厂家软件对比 |
| 数据跳变 | 接地不良、干扰、线松、字序错 | 查屏蔽和接地，换字序 |
| 电量明显偏小 | 倍率没乘、CT 只穿一相、电压缺相 | 核对倍率和接线 |
| 电量为负 | CT 穿反、相序反 | 检查 P1/P2 和相序 |
| 水表脉冲丢失 | 无上拉、防抖太长、脉冲太窄 | 示波器/万用表看脉冲 |
| 4-20mA 不准 | 量程错、采样电阻错、接地环流 | 测回路电流，核对量程 |
| 网关频繁离线 | SIM 卡、天线、APN、供电、MQTT ClientId 冲突 | 看网关日志和信号 |
| 数据时间不对 | NTP 没配、时区错、表内时钟错 | 对时并检查时区 |
| 数据重复 | QoS 1 重发、补传没去重 | 用 `gatewayId + seq` 去重 |
| MQTT 连不上 | 账号密码、ACL、端口、TLS | 用 MQTTX 测试 |
| 蒸汽流量偏差大 | 温压补偿错、直管段不够、冷凝水 | 核对密度和安装 |
| 雷雨后设备损坏 | 防雷缺失、接地不良 | 检查 SPD 和接地 |

## 14. 选型决策树

```text
仪表有 RS-485 吗？
├── 有
│   ├── 协议是 Modbus RTU / DL/T 645？
│   │   ├── 是 → 串口服务器或边缘网关
│   │   └── 否 → 查厂家协议文档，必要时换表或加协议转换器
│   └── 现场有网线吗？
│       ├── 有 → 串口服务器 + 交换机
│       └── 没有 → 4G DTU 或边缘网关
└── 没有
    ├── 有 4-20mA / 脉冲 / 开关量吗？
    │   ├── 有 → IO 采集模块 → RS-485 → 网关
    │   └── 没有 → 加装智能表或传感器
    └── 是 PLC 控制的设备吗？
        ├── 是 → 从 PLC 取数（OPC UA / Modbus TCP）
        └── 否 → 加装智能表

网络怎么选？
├── 有网线 → 以太网
├── 无网线、点位集中 → 4G DTU
├── 无网线、点位分散、低功耗 → LoRa / NB-IoT
└── 多协议、需本地缓存 → 边缘网关
```
